# Security policy

Please do not post vulnerability details in public issues. Contact the project maintainer privately using GitHub's private vulnerability reporting once enabled.

Security priorities: passkeys/MFA for staff, scoped roles and review approval, restricted deployment access, immutable versioned public evidence, authenticated and rate-limited mutations, secure headers, dependency scanning, private R2 objects, backup restoration drills, separation of production/staging, audit trail export, and monitoring.

No public record-editing API is exposed. A public repository is not a writable production database. Staff roles must be enforced server-side and never based solely on hidden UI controls.

Coverage and accuracy errors should be reported with original sources and archived evidence; material corrections must remain publicly inspectable.
